PRIVACY

Recruitment Data

This is a draft technical privacy page for the prototype. Directors should approve the final wording before launch.

Discord authentication

The portal is designed to use Discord OAuth. Applicants authenticate on Discord's own authorization page. Pokémon Void should never ask for or store a Discord password, 2FA code, passkey or Discord session credential.

What the portal needs

The production system should collect only the information required to process recruitment: a Discord account identifier, application answers, selected role, portfolio/supporting material, status history, and interview information if the applicant reaches that stage.

What should never be in the frontend repository

  • Applications or interview transcripts
  • Discord client secrets or API credentials
  • Cloudflare database credentials or encryption keys
  • Director access lists if they expose unnecessary private information

Access

Application information should be available only to authorised recruitment Directors and any explicitly authorised maintainer where technically necessary. The interview system is intended to use a stricter access model agreed with the Directors before implementation.

Retention

Retention and deletion periods are not final yet. They should be agreed before launch so unsuccessful applications and old interview records are not retained indefinitely without a reason.
